# Целостность и синхронизация

Читать при изменении проводок, резервов, импорта, облачной синхронизации или схемы. Источник контрактов — TX/FX/BG/AS/SY/SE и AC в ТЗ, не отдельная копия формул здесь.

| Граница | Что должно сохраняться |
|---|---|
| Сумма | Валюта и её точность обязательны; decimal для курсов/количеств; округление на определённой границе, не после каждой промежуточной операции. |
| Доступ | Сервер получает actor из сессии; проверяет membership всех затронутых account/goal IDs. Клиентский household ID не является доказательством. |
| Повтор запроса | Один operation ID создаёт один финансовый эффект. Тот же ID с другим payload возвращает конфликт, не подменяет исходную операцию. |
| Конкуренция | Две правки одной revision не теряют одну из них. До выбора пользователя версия расчёта обозначена; разрешение конфликта само имеет revision. |
| Перевод | Обе проводки и комиссия фиксируются вместе. При сбое частичная сторона не остаётся. |
| Резерв | Одна сумма не выделяется двум целям и не вычитается повторно из свободных денег. Обязательство внутри категории не второй резерв. |
| Оценка | Snapshot/quote хранит as-of/source; переоценка не генерирует доход или покупку. Исторические расходы не переписываются последним курсом. |
| Удаление | Tombstone синхронизируется; поздний retry не воскрешает удалённую запись молча. Восстановление — явное событие. |
| Импорт | Job фиксирует источник/результат/ошибки; потеря ответа после commit не вызывает повторное создание при retry. |
| Backup | Проверять версию, связи, валюты и пересчитанные итоги в чистом хранилище. Не экспортировать auth-секреты. |

При финансовом дефекте минимальный полезный пример включает исходные счета/резервы, действие, состояние после и ожидаемый итог. Не использовать реальные выписки в репозитории. Прежде чем назвать sync устойчивым, проверить обрыв до/после commit и повторную отправку.
