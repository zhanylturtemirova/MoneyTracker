# Frontend MoneyTracker

Прочитай [AGENTS.md](../../../AGENTS.md), относящиеся разделы [ТЗ](../../../docs/SPEC.ru.md) и существующий клиент. Frontend выбран: Next.js App Router, React и TypeScript со статическим экспортом. Демонстрационная страница есть; офлайн-PWA и синхронизация ещё не реализованы. Не создавай каркас приложения, если поручено только ревью или изменение инструкций.

## Завершённый пользовательский путь

- Реализуй ввод → валидацию → сохранение → повторное чтение → пересчёт. Успешный toast без записи не считается сохранением.
- Финансовые итоги получай из общего доменного модуля; не копируй формулы в карточки. Различай Free now, прогноз, капитал, резервы и реальные остатки.
- Офлайн-операция получает устойчивый ID и статус очереди. Повторный тап/перезапуск не создаёт дубль; не показывай «синхронизировано» до подтверждения сервера.
- При конфликте показывай обе версии и выбор одной без автоматического сложения сумм. Несохранённый ввод сохраняется при ошибке, возврате и открытии клавиатуры.
- Подозрительный OCR допускает редактирование; неизвестные сумма/валюта/счёт оставляют черновик. Неуверенная категория при известных финансовых полях — Needs review. Скриншоты портфеля всегда подтверждаются.
- Удаляй временную копию чека после надёжной записи извлечённых данных, не файл галереи. Не логируй полный OCR-текст или финансовые файлы.

## Платформы

Проверяй API через capability detection. Цель поддержки с 2015 года не равна совместимости со всеми ОС. Для неподдерживаемого Share оставь загрузку файла, для OCR — ручной ввод, для push — внутренний центр. Честно обозначай недоступность офлайн-хранения. Не заявляй delivery/background sync по результату desktop preview.

Сохраняй английский UI, исходные валюты и корректный ввод десятичной запятой/точкой. Отображай источник/дату оценок и неполноту, не точный ноль. Крупные зоны нажатия, масштабирование текста, фокус, темы и экранная клавиатура проверяются на затронутых экранах. OCR-модели и тяжёлые отчёты загружай по требованию, не в критическом пути старта.

## Проверки

Найди команды в конфигурации, не предполагая готовый framework. Проверь главный путь, значимый отказ и повторное открытие данных. Для финансового изменения добавь содержательную регрессию; для визуального достаточно подходящей ручной проверки. Отметь конкретные браузеры/ОС и непроверенные возможности. Нативная упаковка через Capacitor — будущая работа, не основание обещать готовые приложения магазинов.
