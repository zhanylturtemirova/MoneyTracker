# QA MoneyTracker

Прочитай [AGENTS.md](../../../AGENTS.md), относящиеся требования и AC-01–AC-24 в [ТЗ](../../../docs/SPEC.ru.md). Проверь фактическую реализацию и инструменты. Если кода нет, проверяй документ и проектируй сценарии в рамках задачи, не создавай фиктивные тесты продукта.

## Ожидание независимо от реализации

Для каждого существенного случая: ID требования → риск → исходное состояние → действие → наблюдаемый итог. Числовой ожидаемый результат рассчитай независимо, а не вызывая тестируемую функцию повторно. При противоречии теста и ТЗ проверь оба; предложения P не становятся подтверждёнными по факту прохождения теста.

## Приоритетные проверки

- Деньги: перевод и резерв не расход; бюджетный расход уменьшает остаток бюджета вместе с деньгами; комиссия отдельна; FX/суммы чека не создают вторую покупку; отрицательная свободная сумма видна.
- Импорт: суммы с запятой/точкой, неизвестная валюта, повтор чека, две похожие реальные покупки, удаление копии после записи. Для скриншотов повтор не увеличивает количество, пропуск позиции не продаёт её.
- Активы: позиции разных брокеров отдельны; неизвестная цена/себестоимость не становится нулём; переоценка не считается зарплатой; депозит использует выбранные условия.
- Семья: запрос другого household через прямой API запрещён, даже если UI скрывает ссылку. Оба приглашённых участника видят личные и общие счета семьи согласно ТЗ.
- Офлайн: повтор запроса после потери ответа, перезапуск, две версии одной записи, выбор одной, удаление/восстановление и полная резервная копия.
- Платформы: Android/iPhone, старый и современный браузер, отсутствие OCR/Share/push, клавиатура, крупный текст, тема. Пройти fallback, не только наличие кнопки.

Чистые формулы проверяй unit-тестом; транзакции, авторизацию и гонки — реальным изолированным хранилищем; поток — пользовательским сценарием; доставку ОС — устройством. Mocks сети допустимы для воспроизводимости, но не заменяют проверяемую интеграцию. Не ослабляй assertions ради зелёного отчёта и не вводи специальные ответы для тестовых ID.

## Выполнение и отчёт

«Написать тесты» — написать и запустить, когда окружение доступно. «Ревью» — сообщить дефекты без непорученной реализации. Для регрессии по возможности подтвердить падение до исправления. Сообщай команды, требования, результат и непроверенные платформы; различай passed, failed, not run и not applicable. Успешная проверка Markdown не доказывает работу приложения.
